The help text lists the three modes: bulk (RNA-seq reference profiles), wes (whole-exome reference profiles) and scrna (demultiplexing a pooled sample). The PATH change only lasts for this terminal window. Add the same line to ~/.bashrc to keep it.

2How the pipeline works

Every person's genome carries a unique combination of common SNPs: positions where people differ, such as G or C at one base. Cell lines inherit the SNPs of the person they came from, so a few thousand SNP genotypes act as a fingerprint for each cell line.

The pipeline works in two halves that meet at a shared database:

A · Build a fingerprint for each cell line modes: bulk, wes
FASTQ reads→ align (STAR for RNA, BWA for WES)→ pile up reads at 7M common SNPs→ call genotypes 0/0 · 0/1 · 1/1→ shared database
B · Assign each cell in a pool mode: scrna
pooled scRNA BAM→ count alleles per cell (cellsnp-lite)→ cluster cells by genotype (Vireo)→ match to database→ cell → cell line

The 7M SNP positions are the common variants (allele frequency above 5%) from the 1000 Genomes Project. The database currently holds fingerprints for 54 runs: 44 RNA-seq cell line profiles and 10 WES organoid samples.

Vireo can run in two ways, and that difference is what the group exercise is about:

  • Guided: you tell Vireo which cell lines are in the pool, and their fingerprints from the database are used as the starting point.
  • Unguided: Vireo only knows how many donors to look for. It groups cells by genotype first, and afterwards each group is compared with every fingerprint in the database.

One SNP can't tell seven lines apart: four of them are 1/1 here. The pipeline combines tens of thousands of positions. CACO2 has no call because too few reads covered this position in its RNA-seq data. Fingerprints from RNA only see expressed genes.

5Group exercise: one pool, four runs

Pool_ctr is a single 10x Genomics run with 10,308 cells from seven colorectal cancer lines. The per-cell allele counts (the cellsnp-lite step) are already computed, so each run starts at the genotype-matching step.

The twist: DLD1 and HCT8 were derived from the same patient, so their fingerprints are almost identical. Each group gives Vireo different information about the pool:

6Draw your cell composition, then compare

Each group draws the cell composition of its own run, then we put all four side by side. Copy the notebook to your own folder, so you can edit and save it.

terminal
cp /groups/nils/data/scrna_pipeline/code/notebooks/06_demo_compare.ipynb ~/scrna_demo/
code ~/scrna_demo/06_demo_compare.ipynb
  1. In VS Code, click Select Kernel (top right) → Python Environments… → Enter interpreter path, and paste /groups/nils/data/scrna_pipeline/env/bin/python
  2. In the first code cell, set MY_RUN to your group's ID, for example MY_RUN = 'group3_no_hct8'.
  3. Click Run All. Section 1 of the notebook draws your run's cell composition.
  4. When every group has its graph, re-run section 2: all four compositions side by side, on the same scale and in the same bar order.

How to read the composition graph: one bar per cell line, with its cell count on top. Dark green = matched (guided, or a confident database match), orange = matched with low confidence, dark grey = a Vireo donor that matched no fingerprint, red = doublets (the dark red part is HCT8+DLD1 pairs), light grey = unassigned.

A run that hasn't finished yet is replaced by its pre-computed copy, and the graph title says so. The unguided run (Group 2) takes about 80 minutes. No VS Code? Set MY_RUN in the copied file with any editor, then run jupyter nbconvert --to html --execute ~/scrna_demo/06_demo_compare.ipynb and open 06_demo_compare.html.

7Discussion

  1. Which run assigned the most cells to a single line? Does more assigned mean more correct?
  2. In the full 7-line run, why are so few cells called DLD1 or HCT8, and what is the dark red part of the doublet bar?
  3. What happens to HCT8 cells when HCT8 is left off the list? And to DLD1 cells when DLD1 is left off?
  4. The unguided run needs no prior knowledge. What does it get right, and where does it struggle?
  5. What does this mean for designing a pool, and for reporting which cell lines you sequenced?
Facilitator notes: what the pre-computed runs show
RunAssigned to a lineDLD1HCT8"HCT8+DLD1 doublet"Unassigned

Unguided6,508000662 + 1,803 unmatched

Guided, no DLD18,636—34001,123

The key point: genotypes identify the donor, not the cell line. Given both DLD1 and HCT8, Vireo can't choose between two near-identical fingerprints and calls about 200 cells a mixture of the two. Given only one, it sends that whole family (about 340 cells) to whichever sibling is on the list. The guided runs therefore look more successful when a line is left out, even though they can't be right about which sibling the cells are.

Unguided: three of the seven donors are matched. RKO (concordance 0.90) and HCT116 (0.87) are matched with high confidence, HT29 (0.83) with low confidence because its lead over the runner-up is small. The other four donors (1,803 cells) stay unmatched: with one-to-one matching, their best remaining fingerprint scored only 0.71–0.75, below the 0.80 threshold. So CACO2, LIM1215 and the DLD1/HCT8 family never appear by name. The unguided run also calls far more doublets (1,335 vs 701). Knowing what is in the pool helps a lot. Without that knowledge, the pipeline still finds the large populations and reports the rest honestly as unknown, instead of guessing.
